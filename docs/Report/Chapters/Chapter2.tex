\chapter{Related Work}
\label{ch:related-work}

\begingroup
\setaftersecskip{6pt}
\setlength{\emergencystretch}{2em}
This chapter shows how the thesis relates to previous research on virtual exhibitions and immersive search systems. It considers three areas that are important for the developed VR museum: virtual exhibitions, immersive multimedia retrieval, and content-based exploration of virtual museums. While previous works cover parts of these areas, the systems do not combine cross-media search, dynamic exhibition creation, and continued exploration in an interactive VR museum.

\section{Virtual Exhibitions}
\label{sec:related-virtual-exhibitions}

Virtual exhibitions solve a space problem. Digital collections can be much larger than the physical exhibition space that is available. In a virtual environment, the same objects can be used in different groups and can be accessed independently of their physical location.

\paragraph{VIRTUE}
VIRTUE is a system for creating and viewing virtual exhibitions. Curators use the web-based Virtual Reality Exhibition Manager User Interface (VREM-UI) to create rooms and place images, videos, and 3D artifacts. The Virtual Reality Exhibition Manager (VREM) manages the exhibitions and stores them together with the artifacts and their metadata in MongoDB. Visitors view the resulting exhibition through the Virtual Reality Exhibition Presenter (VREP), a VR frontend implemented in Unity. In the original VIRTUE system, exhibitions are created manually and are not generated from a search query \citep{giangreco2019virtue,peterhans2022galleries}.
\citet{peterhans2022galleries} add automatic image galleries to VIRTUE. To create these galleries, VREM connects to Cineast. The image features were extracted earlier by Cineast and are stored in Cottontail DB. VREM uses these features to build the exhibition. Figure~\ref{fig:virtue-architecture} shows how the different components are connected \citep{peterhans2022galleries}.

\begin{figure}[htbp]
  \centering
  \includegraphics[width=\textwidth]{Figures/ch02-01-virtue-architecture.pdf}
  \caption[Architecture of VIRTUE with automatic gallery generation]{
    Architecture of VIRTUE with its automatic gallery-generation extension. The VREM-UI is used to create and manage exhibitions, VREM stores exhibition data in MongoDB and serves it to the VR presenter, while Cineast and Cottontail DB provide the image features used to generate galleries \protect\citep[Fig.~1]{peterhans2022galleries}.

For the arrangement, the system trains a Self-Organizing Map on image features extracted earlier. Each node is assigned a representative image. When this image is selected, a sub-room with more images assigned to the same node is created \citep{peterhans2022galleries}.

\paragraph{Space-Adaptive Artwork Placement}
\citet{kim2024spaceadaptive} focus on how artworks are arranged. Their system uses a 3D model of a museum and a set of paintings. It creates thematic groups of artworks and uses five adjustable content-similarity factors: color, material, description, artist and production date. An algorithm then places the artworks based on four cost functions: intra-cluster distance, inter-cluster distance, intra-cluster intervisibility, and occupancy. Artworks in the same group should be close to each other and easy to see, while different groups should stay separate. Figure~\ref{fig:space-adaptive-placement} shows this process.

\begin{figure}[htbp]
  \centering
  \includegraphics[width=\textwidth]{Figures/ch02-02-space-adaptive-placement.pdf}
  \caption[Workflow of space-adaptive artwork placement]{
    Workflow for space-adaptive artwork placement. Curator-defined weights first guide the measurement of artwork similarities and clustering. The resulting groups are then placed in the available museum space and iteratively optimized against spatial constraints \protect\citep[Fig.~1]{kim2024spaceadaptive}.
  }
  \label{fig:space-adaptive-placement}
\end{figure}

These works create exhibitions that are ordered by content or improved for the available space. The prototype developed here follows a different approach. Instead of curating an exhibition in advance, it builds an exhibition from an already ranked result set from the vitrivr-engine. A new text or similarity query replaces this exhibition and continues the exploration.

\section{Immersive Multimedia Retrieval}
\label{sec:related-immersive-retrieval}

The second research area uses immersive environments as user interfaces for multimedia retrieval, not as exhibition spaces. Users can create queries and view the results directly in a three-dimensional space.

\paragraph{vitrivr-VR}
vitrivr-VR is a VR interface for video search. In the 2022 version, Cineast extracts features and processes queries. Cottontail DB then stores the data and performs similarity searches. The Unity frontend communicates with Cineast through a RESTful API. Users can search by concept, text, Boolean rules, location, time, or pose. Spoken text is processed offline and the results appear on a cylinder around the user \citep{spiess2022vitrivrvr}. This brings both searching and viewing the results into VR. The system in this thesis still uses text and similarity search, but shows images, videos, and 3D models as exhibits that visitors can walk around.

\paragraph{MediaMix}
MediaMix brings multimedia search into an MR environment. The application uses the Apple Vision Pro and arranges results spatially. MediaMix supports the vitrivr-engine as one of its retrieval backends. In this configuration PostgreSQL with pgvector provides database and vector-search support. Users interact through gaze and gestures, with a keyboard available for input. Results are shown on spheres with configurable density, on two-dimensional panels that float in the room, or attached to a virtual wall. Multiple result spheres can be merged, and similar results can be placed close together \citep{arnold2026mediamix}. MediaMix and this thesis both use the vitrivr-engine and spatial retrieval interfaces. In the VR museum, images, videos, and 3D models are presented together as exhibits and explored through a series of queries.

\section{Content-Based Exploration in Virtual Museums}
\label{sec:related-content-exploration}

Systems where a search query, a selected exhibit, or the user’s behavior leads to further exploration are especially relevant to this thesis. The automatic VIRTUE extension is one example, because selecting a representative image opens a more specific sub-room \citep{peterhans2022galleries}.

\paragraph{Query-Based Exhibition Generation}
\citet{hayashi2020internet} turn a database search directly into a virtual exhibition. Users enter keywords to search for artworks, and the matching results are automatically arranged in a 3D museum environment.
This already links a search directly to an exhibition. However, it only works with images and metadata and visitors cannot continue by running a cross-media search from an exhibit.

\paragraph{Content-Based Navigation}
\citet{koutsoudis2012navigation} connect a web-based virtual museum with content-based search for 3D artifacts. Visitors can inspect and rotate exhibited vessels and view information about them. A vessel can also be used for a query by example. A server then calculates the similarity of its shape to those of the other models. However, it is a non-immersive web application, and the search is limited to a uniform collection of 3D vessels.

\paragraph{Virtual Art Exhibition System}
The Virtual Art Exhibition System uses viewing time to choose the topic of the next exhibition. It begins with eight artworks in one room. An invisible area with a radius of two meters around each image records how long the visitor stays nearby. After the visitor moves away, the system checks which artwork they looked at for the longest time. The system then creates a new exhibition with works related by period, artist, or country. Figure~\ref{fig:virtual-art-interest} shows this process \citep{fukuda2023virtualart}.

\begin{figure}[htbp]
  \centering
  \includegraphics[width=0.82\textwidth]{Figures/ch02-04-virtual-art-interest.pdf}
  \caption[Generation of an exhibition from visitor interest]{
    Interest-driven generation of a follow-up exhibition. The system saves how long the visitor stays near each artwork. It then uses the artwork viewed for the longest time to find related works based on its period, artist, and country \protect\citep[Fig.~2]{fukuda2023virtualart}.
  }
  \label{fig:virtual-art-interest}
\end{figure}

\citet{meinecke2022contextualizing} also support continued exploration. Their online virtual museum connects each artwork to related images. Visitors can filter the collection by artist, style, or detected object classes and can use several visual views. The system combines similarity search with browsing in a virtual museum, but it only works with images and runs in a web browser.

These works are closer to the interaction model of the VR museum than a general method for 3D model search. They use a text query, a selected exhibit, observed interest, or filters to get to more works. Like VIRTUE, this thesis presents different media types in VR. Like vitrivr-VR and MediaMix, it uses the retrieval backend. Like the systems for content-based navigation, it allows continued exploration. The contribution is to combine these features in one process. An exhibit directly starts a cross-media similarity search, and every result set appears as a new, fully immersive exhibition.
